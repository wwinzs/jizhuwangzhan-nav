# 记住网站 · 个人导航（v1.9.30-RC 开发候选）

独立原创的全屏个人导航主页，参考 iTab 的桌面理念，不包含 iTab 源码或品牌资产。

**导航主页默认依然是可独立使用、数据保存在浏览器中的静态网站**，不需要数据库才能查看、管理或导入导出收藏。v1.9 开发分支另外提供可选的 PHP/MySQL 私有站长账号服务，**仓库内 `account-flags.js` 的登录和找回开关均默认关闭**；部署该前端文件不会自动启用站长账号。

## v1.9.30-RC 发布状态（尚未上线）

- 正式使用的导航页面与 VPS 仍保持原有部署状态；当前 GitHub Draft PR #10 中的 v1.9.30 仅是**发布候选**。
- [v1.9.30 发布验收与回滚清单](RELEASE_V1930_RC.md)：列明真实数据库备份、增量迁移、手机/电脑浏览器 Cookie/CORS、真实 SMTP 邮箱、Nginx/PHP-FPM 隔离等正式发布门槛。
- GitHub Actions 分别提供静态前端 RC ZIP（含 SHA-256）和宝塔后端 Draft ZIP；**它们不能作为无需审批的在线升级脚本**。原有数据库禁止重复运行全新安装程序。
- 前端的两个开关只控制网页入口，**不能代替 API 服务端的鉴权或外部网络访问控制**。站长账号功能在生产环境必须经过真实浏览器验证并单独批准后才能开放。

## 已实现功能

- 摄影壁纸与渐变回退背景、自定义本地壁纸、深色与浅色主题
- 实时时钟、日期问候语、月历、随手记
- 百度、必应、Google 搜索，支持 Ctrl/⌘ + K 快捷键
- 分类导航、添加/编辑/删除网站、常用收藏、名称筛选与拖动排序
- 分类新建、重命名、删除时保留网站
- 本地自动存储、导入/导出 JSON、恢复默认
- 电脑、平板、手机自适应
- GitHub Actions 代码检查和自动部署工作流

## 运行方式

无需安装依赖，下载仓库后直接打开 index.html 即可预览；在生产环境建议使用 HTTPS 静态站点或 GitHub Pages。

## GitHub Pages 上线

1. 进入仓库 Settings → Pages。
2. Build and deployment → Source 选择 **GitHub Actions**。
3. 合并本项目的功能分支至 main；随后在 Actions 查看 “Deploy navigation to GitHub Pages”。
4. 当部署运行成功后，预计访问地址是 https://wwinzs.github.io/jizhuwangzhan-nav/ 。以 GitHub Actions 发布的真实页面地址为准。

如尚未启用 Pages，需要先完成第 1–2 步才能正常部署。站点不会自动成为浏览器“新标签页”，要替换新标签页需要另行开发浏览器扩展。

## 设计与数据说明

数据仅保存在当前浏览器的 localStorage，不会在多台电脑或浏览器之间同步。**清除网站数据、换浏览器或换设备前，请导出 JSON 备份。**

用户自定义壁纸支持 PNG / JPEG / WebP，限 2MB。导入备份有数量、长度、网址协议和文件大小检查。所有网址只允许 HTTP/HTTPS，禁止脚本或文件协议。此项目不使用第三方跟踪脚本。

本项目为首版，建议在后续版本增加：移动端拖动排序、快捷网站图标自动获取、多设备同步、PWA / 浏览器扩展、自动化端到端交互测试。GitHub Actions 的语法检查**不是**对所有交互与浏览器兼容性的完整验收。

## 代码结构

- index.html：页面语义结构与弹窗
- style.css：原有交互布局基础样式
- desktop.css：iTab 风格的壁纸优先桌面布局、紧凑组件、无底板网站图标
- app.js：页面状态、收藏管理、持久化与数据校验
- favicon.svg：网站图标
- .github/workflows/check.yml：自动语法检查
- .github/workflows/deploy.yml：GitHub Pages 发布

注意：移动端排序仍需后续实现触控拖动，目前通过设置开启的排序模式使用鼠标拖拽。


## v1.3 稳定性与数据恢复
- 如果读取到损坏的导航 JSON，不会静默覆盖原数据。首页出现恢复警告，可下载原始文件，用户明确确认后才重置。
- 本地存储失败时，修改会回滚到最后成功保存的快照，不再错误提示成功。
- 在「我的常用」新增网站，默认自动设为常用，保存后立即可见。
- 分类新建和编辑统一为自定义弹窗，允许设定分类图标。
- 新增 tests/stability-smoke.html 浏览器回归测试，覆盖异常数据、无法写入、分类编辑及收藏流程。
- 当前依旧是浏览器本地存储；墙纸体积可能接近存储额度上限，请定期导出 JSON。IndexedDB 壁纸存储与多设备同步将在后续版本单独设计和迁移。

## v1.4 触屏与键盘排序

- 自动化浏览器测试新增 tests/sorting-smoke.html，覆盖触屏模拟、键盘与持久化。

## v1.5 网站文件夹
- 首页新增文件夹入口。文件夹可以在桌面或设置中创建，归属于已有分类。
- 打开文件夹查看内部网站，可以从文件夹内新增网站、打开网站、编辑、移出桌面、上移和下移。
- 编辑网站时可以指定文件夹；先选择分类，再选择该分类下的文件夹，或保持桌面。
- 文件夹重命名与分类调整会同步更新内部网站的分类。删除文件夹不删除网站，网站自动回到所属分类的桌面。
- 旧版 localStorage JSON 和备份中没有 folders 属性时按空文件夹处理，原始收藏网站不会丢失；导入包含文件夹的备份也会验证文件夹数量、合法分类及链接归属。
- 新增 tests/folders-smoke.html 浏览器回归测试。未实现将文件夹拖到图标任意坐标、文件夹嵌套、跨设备同步；这些功能在未来版本中再评估。

## v1.6 电脑桌面布局与组件管理
- 电脑宽屏（至少 851px）可在设置中启用「自由排列」。可点击图标再点空白位置放置，也可拖动互换，保留空位并保存至原 JSON 备份。
- 在自由排列模式下通过「完成布局」保存展示；「自动整理」清除手动位置并回到紧凑网格。分组和移动端自动采用流动排列，不出现不必要的空白。
- 可配置今日灵感、轻日历和随手记的显示开关、排序、紧凑/标准/宽版尺寸；组件可以放在网站区域上方或下方。
- layout 是可选的新字段，旧 JSON 备份继续按自动布局加载。非合法位置、无效组件设置均进行约束与默认修复。
- 手动桌面布局暂时不是完全像素级自由拖放，而是有空格位的网格摆放，避免多尺寸下严重重叠。


## v1.7 壁纸、主题、图标和搜索
- 壁纸选择采用缩略图浏览；新增亮度（45%–100%）与背景模糊（0–8px）滑块及移除自定义壁纸。设置和备份均在原有 localStorage 结构内保存。外部内置壁纸依然依赖 Unsplash 网络，断网时可显示渐变回退背景。
- 完善浅色主题下的组件、设置弹窗与表单颜色，避免之前深浅文字冲突。
- 网站图标可选择自动获取、字符图标、自定义图片三种模式；上传图片限 80KB，支持 PNG/JPG/WebP，保存在站点 JSON 数据中（自定义图标越多，浏览器存储占用越大）。
- 搜索框可直接识别安全的 HTTP(S) 地址和单个域名；新增自定义 HTTPS 搜索引擎网址，模板中必须恰有一个 %s，用于经 URL 编码的搜索词。没有开启第三方搜索建议，也不新增后台接口。
- 老版本备份缺少这些新增字段时自动按默认设置加载，保持数据兼容。
- 浏览器检查新增 tests/personalize-smoke.html，覆盖主题切换、壁纸控制、图标上传、搜索校验和旧数据恢复。


## v1.8 数据基础强化
- 新增本地数据容量估算与大数据提醒、完整 JSON 备份及恢复入口。容量是导航数据的序列化大小，不代表浏览器的实际可用磁盘空间。
- 新增浏览器书签 HTML 导入（最多 2MB），仅提取 HTTP/HTTPS 网址、按书签目录自动建立分类、对现有网址去重，先确认后一次性追加，不会覆盖当前收藏。
- 限制累计 500 个网站、50 个分类；书签导入超限会跳过新增项，并在确认前展示结果。JSON 文件导入限制 8MB，实际本地保存仍取决于浏览器配额。
- 多标签页编辑增加写入冲突检测，拒绝覆盖来自其他标签页的已更新数据；刷新后可以加载较新内容。
- 大于 240KB 的壁纸自动缩放并转换为 WebP；小图片保持原格式。所有数据依旧存于浏览器，暂未实现 IndexedDB 云端同步。
- 增加浏览器回归测试 tests/data-smoke.html，覆盖导入、去重、不安全地址、数据保存冲突和图片压缩。
- 账号/登录/云同步未在此版上线，之后将使用独立的 PHP/MySQL 后端和私有账号策略。


## v1.8.1 — 中国大陆访问优化（静态资源本地化）

- 五套内置桌面壁纸及对应选择器缩略图改为随站点部署的 `assets/wallpapers/*.svg` 本地矢量文件，避免依赖 Unsplash 跨境图片请求；这些是风格化矢量场景，替换原有远程摄影图片，原始名称与主题选择保留。
- 网站图标默认只显示本地字符图标，不自动连接 Google 图标服务。可在设置「图标加载与国内访问」显式选择「尝试从收藏的网站加载图标」。选择后图标直接从相应网站的 `/favicon.ico` 以 lazy loading 请求，失败则保留文字图标；不会将用户的收藏域名发送给 Google 图标汇聚接口。无法保证每个网站都公开 favicon。
- 自定义图标、用户上传的壁纸、JSON 备份恢复、已有 v1.8 存储数据保持可用。旧数据未包含 `faviconPolicy` 时默认本地。
- 额外增加 `tests/mainland-smoke.html` 浏览器测试，检查五套本地资源、图标按需加载、Google/Unsplash 依赖清理、存储设置与旧版兼容。
- 如果正式网站在中国大陆 VPS 上独立部署，更新时**必须一并上传 `assets/wallpapers/` 目录**；只上传 CSS/JS 会导致壁纸丢失。GitHub Pages 部署产物及本地打包须包括此目录。
- 本次仅升级静态导航前端，账号 API 与 `nav.wwinzs.cn` 线上 VPS 不会通过合并 GitHub 代码自动更新；后续需单独上传静态文件到 VPS。
