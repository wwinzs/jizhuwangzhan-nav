# 记住网站 v1.9 — 发布门禁与回滚演练（v1.9.12 Draft）

> **当前仅供评审，不是上线授权。** 正式导航页仍为 v1.8.1，本 PR 代码未部署到 VPS。禁止仅因 GitHub CI 通过而合并、执行迁移、启动 Worker、打开登录或找回开关。

## 一、升级前需要保留的证据

1. **范围隔离：** 只涉及 `api-nav.wwinzs.cn` 的专用站点、专用 MySQL 数据库及 API 的私有 PHP 配置。记录维护窗口、站点根路径、当前 PHP 版本、Nginx 配置摘要；不得触碰其他项目。
2. **可恢复备份：** 对 API 程序、数据库和私有配置分别做权限受限的备份。数据库备份必须包含完整数据结构、唯一账户、会话、限流和所有现有对象；至少在隔离数据库执行一次真正的恢复演练。不要把备份或凭据上传到网页目录和 GitHub。
3. **版本锁定：** 保存当前运行代码/配置的受保护副本及其哈希，确定经过全部 CI 的开发提交和审核人。禁止用 `unzip -o` 覆盖现有 `server/config.local.php`，也不要重新运行 `install-baota.php`。
4. **只读数据库状态：** 运行 `php server/scripts/preflight-upgrade.php`（在私有 API 代码和现有配置均可访问时）。只输出状态、已完成迁移数量和下一编号。4 表应显示需要 `001`；5 表需要 `002`；6 表需要 `003`；7 表且账户/字段正确才显示 `READY`。返回 `BLOCKED` 时必须停工调查，不要自动创建或删除表。非 READY 会返回非零退出码，这是有意设置的部署阻断条件。
5. **部署前必验：** Nginx `root` 精确指向 API `server/public`，网页不允许下载 `config.local.php`、`.user.ini`、源代码、迁移 SQL 或 CLI 脚本；检查 PHP-FPM `open_basedir`、Unix 用户及文件权限确实生效。确认 HTTPS/HSTS 只返回期望的一份配置；真实跨域 Cookie 登录及退出需由浏览器实测，不能只凭 curl 预检。

## 二、升级次序（都需要单独人工确认）

- **Stage A — 备份/恢复门禁：** 先证明已有 API 可用，保存恢复点和回滚证据。现有数据库据早期 VPS 检查可能是 4 表，但必须以本次只读预检为准。
- **Stage B — 数据库：** 根据只读检查结果，在受控维护窗口，依次人工审核并运行所需的 *增量* SQL：`001_security_events.sql`、`002_password_reset_tokens.sql`、`003_async_reset_mail.sql`。MySQL DDL 通常无法完整事务回滚；每次执行后重新只读检查表、关键列、唯一站长账号和原始账户哈希/会话状态。不得越级跳过迁移。
- **Stage C — API 代码：** 在保留 `config.local.php` 和 `app_key` 原值的前提下以原子/可回退方式替换专用 API 代码；不能把全新安装包当成升级脚本。前端账号开关、`password_reset_enabled` 与 Worker 都保持关闭，先做健康检查、旧账号真实登录和退出。
- **Stage D — Worker 审核：** 用受控的 CLI 用户读取私有配置，先执行 `php server/scripts/preflight-worker.php`。它拒绝 world/group 可读的配置、错误运行身份、错误 HTTPS 原点、缺失扩展、未完成迁移或异常队列。**这是只读检查，不会试发邮件**。生产 SMTP/域名所有权、SPF/DKIM/DMARC、真实收发、告警与 Worker 超时处理都合格后，才可单独申请启动定时器并开启邮件找回；若尚未开启 SMTP，Worker 预检返回非零属预期。
- **Stage E — 前端：** 必须等浏览器从 `https://nav.wwinzs.cn` 的真实 HTTPS 页面验证完整 Cookie/CORS/修改密码/令牌去痕，才能分别申请启用登录和邮件找回。开启登录不会自动开启找回。

## 三、回滚/事故边界

- **发现异常时：** 先禁止新密码找回请求，停止 Worker/定时器（如果曾人工启用），保持私有日志与数据库现场，避免继续创建不确定投递的重置令牌。
- **API 代码回滚：** 在兼容性经审核确认后切换回受保护的旧代码快照，保留原 `config.local.php` 和密钥。新增的表保持原状，不因回退代码直接 `DROP TABLE`。若旧代码无法读取升级后数据，暂停回滚并核查依赖。
- **数据库恢复：** 禁止盲目覆盖正在使用的数据库。先将备份恢复到隔离数据库，核验账户、哈希、数据与迁移版本；再由维护者决定是否需要维护窗口内的受控恢复。恢复旧备份可能使后续密码修改/会话撤销回退，必须评估账户安全并重新验证所有旧会话。
- **SMTP 不确定结果：** 单次任务只尝试发送一次。SMTP 超时或 Worker 崩溃可能丢邮件、也可能已被邮件服务商接受；绝不强制重发旧任务。由站长重新发起申请，核实重复投递风险。
- **审计记录/证据：** 记录每个审批时间、检查命令退出码和 CI 运行链接。严禁上传站长密码、授权码、重置链接、Cookie、数据库连接串和备份内容。

## 四、GitHub CI 的真实覆盖与缺口

- 隔离 MySQL 8 测试：4→5→6→7 表增量升级、非法混合表阻断、站长哈希不变、禁用账号阻断。
- 配置权限测试：可公开读取的私有配置必须阻断 Worker；受保护权限才可通过。
- 原有登录、会话、密码安全、异步邮件及模拟 TLS 邮箱测试保留。
- **仍未验证：** 实际 VPS 的全量备份恢复、PHP-FPM `open_basedir`、Nginx 外部可访问性、真实浏览器 Cookie/CORS、邮箱真实投递、生产系统用户及真实 Worker 定时器。CI 不能替代这些实机验收。

本手册不会部署程序，也不会对用户的服务器执行任何命令。

## v1.9.30-RC 隔离恢复与只读 HTTPS 实机检查（2026-10-20 开发）

- CI 新增 `server/tests/backup-restore-ci.sh`：只允许 `CI=true` 的合成 `nav_ci` 数据库，将七表真实导出到私有临时目录，恢复至另外新建的 `nav_restore_ci`，对比全部七表数量、原站长哈希、外键/索引及合成收藏文档与会话，再清理测试环境。**这不是 VPS 上的真实数据库备份或真实灾难恢复演练**。
- 新增 `server/scripts/check-edge-readonly.sh`：审核完成并安全放到服务器指定私有代码路径后，运维可以在交互式 SSH 终端执行 `bash server/scripts/check-edge-readonly.sh`。脚本只对本机 `127.0.0.1:443` 所映射的 `api-nav.wwinzs.cn` 域名执行 **GET / OPTIONS**，不输入密码、不读取 Cookie、不执行数据库更改。检查 HTTPS CA/域名证书、API 健康响应、可信 Origin 的跨域预检、恶意与缺失 Origin 的阻断、后端私有路径必须 403/404、单一 HSTS 头。**不会测试真实公网接入或浏览器 Cookie，也不会改变 Nginx 配置**。
- 此前 VPS 本机 HTTPS 预检报告曾出现两份 `Strict-Transport-Security` 头；只读脚本将此情况视为 **BLOCKED**。正式发布前须经授权后检查 Nginx 与 PHP 谁负责发送 HSTS，避免两个位置叠加。不得为了让检查通过直接删除全部 HSTS。
- 宝塔 API Draft ZIP 的 CI 现在也提供 `.sha256` 校验文件，前端 v1.9.30-RC ZIP 同样提供 SHA-256。保留工作流名称、源提交与校验摘要作为发布证据；对不上哈希立即停止。
- 如果生产数据恢复、真实浏览器跨域 Cookie、HSTS 单一头、权限隔离或真实邮件收发仍未验证，**不得将 v1.9.30-RC 宣称为 GA 正式可用版**。
